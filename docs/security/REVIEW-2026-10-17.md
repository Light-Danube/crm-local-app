## Підтверджені локально проблеми

## Додаткові ризики з аналізу коду

- **P0: необмежене споживання ресурсів.** У multer немає `limits`, квот або admission control; запис відбувається до перевірки запиту. `/youtube/:videoId` не має лімітів конкурентності, deadline чи скасування upstream після від'єднання клієнта (`server.js:179–205`). Зовнішні потоки не мають окремого `error` handler. Навантажувальну перевірку не проводили.
- **P1: HTTP і WebSocket origins.** `app.use(cors())` дозволяє читання HTTP з довільного origin (`server.js:21`); `new Server(server)` не перевіряє origin/authentication для WebSocket handshake. CORS не замінює авторизацію й сам по собі не захищає WebSocket. Потрібні явні допустимі origins і окрема політика для клієнтів без Origin.
- **P1: чужі медіа.** `/uploads` публічний, а `video uploaded` довіряє довільному `videoId`; немає перевірки session ownership. Непередбачуване ім'я файлу не є дозволом доступу.
- **P1: payloads і ліміти подій.** Час, гучність, URL, boolean-параметри й назви сесій не мають серверної валідації та обмеження частоти. `video url` може отримати не string; клієнтський `url.match()` тоді впаде. Інші форми payload можуть мати інші наслідки; повний fuzzing не виконувався.
- **P1: журнали й завершення.** `await logStream.write()` очікує boolean, а не flush/backpressure; stream error handler відсутній. Файл журналу вибирається лише під час старту, ротації/retention немає. SIGINT використовує зарезервовану подію `disconnect` і не закриває коректно HTTP/Socket.IO/log stream (`server.js:208–219, 413–430`).
- **P2: HTTP range.** Самописний parser не підтримує suffix ranges і multi-range, відповідає 400 замість 416 на частину некоректних діапазонів; є `statSync` і відсутні stream error handlers (`server.js:96–139`). Наслідок — збої перемотування та зайве блокування event loop.

Не заявляємо довільний SSRF для YouTube: hostname у коді фіксований; потрібна окрема перевірка поведінки бібліотеки/redirects. Так само не заявляємо path traversal через multipart-ім'я: підтверджений шлях читання — `/videofile/`.

Найважливіші групи:

- `proxy-addr@2.0.7`: npm позначає **critical**, [GHSA-jqcg-44mw-7w3h](https://github.com/advisories/GHSA-jqcg-44mw-7w3h), виправлений діапазон починається з 2.0.8. Advisory стосується spoofing через IPv4-mapped IPv6 trust subnet. У застосунку не задано `trust proxy` і не знайдено використання `req.ip` для авторизації; експлуатаційність саме цього advisory тут не підтверджено. Це не причина називати весь застосунок «critical exploit».
- `socket.io@4.7.4` → `engine.io@6.5.4`, `socket.io-parser@4.2.4`, `socket.io-adapter@2.5.2`, `ws@8.11.0`: кілька DoS/advisory, зокрема [polling exhaustion](https://github.com/advisories/GHSA-r635-g3xr-vw7x) та [parser memory exhaustion](https://github.com/advisories/GHSA-2m8v-j782-fhvr). Engine.IO приймає polling за замовчуванням; вимкнення polling лише на одному клієнті не закриває серверний шлях. WebTransport advisory не доводить доступність цього transport у поточному сервері.
- `express@4.22.1` → `qs@6.14.1`, `body-parser@1.20.4`, `path-to-regexp@0.1.12`: query parsing і routing advisories. Поточні маршрути не мають кількох параметрів в одному сегменті; reachability конкретного route ReDoS не доведена. Body parser middleware прямо не підключено.
- `reload@3.2.1` тягне старі `serve-static@1.15.0`, `send@0.18.0`, `ws`; `uuid@9.0.1` має moderate advisory. Обидва оголошені production dependencies, але їх імпорти в коді застосунку не знайдені. Перевірити й прибрати невикористані залежності окремим PR; не переносити їх автоматично в dev без потреби.
- Dev-дерево додає `brace-expansion`, `braces`, `picomatch` high findings. Для поточного `npm start` dev-залежності теж використовуються (nodemon), тому це не просто «неважливі локальні пакети».
- `cors` імпортується сервером, але не оголошений прямо; зараз він доступний транзитивно через Socket.IO. Це крихкість dependency contract, а не окрема підтверджена CVE.

Не виконували `npm audit fix`, major upgrades або зміну expected integrity. Подальший PR має зафіксувати реальні resolved версії, повторити full/prod audit і функціональні перевірки; `fixAvailable` не гарантує безпечну сумісність.

## Межі перевірки й наступні кроки

HTTP smoke, upload/download/range і Socket.IO pairing/play/pause успішні на baseline. Вони співіснують із наведеними дефектами. Browser decoding, autoplay, реальна затримка/дрейф, зовнішній YouTube і production TLS/proxy не перевірялися. Немає справжнього test runner (`npm test` — placeholder), CI та benchmark baseline.

Першими потрібні S1–S4 й обмеження ресурсів; потім оновлення залежностей, відновлення з'єднань і вимірювана оптимізація. Послідовність малих PR і критерії приймання наведені в [роадмапі](../ROADMAP.md).
